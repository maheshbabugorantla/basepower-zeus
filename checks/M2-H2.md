# M2-H2 — Territory gate vs an independent source

Done by: orchestrator session (Claude), 2026-09-26.

## Why not Base's address checker
Base's address checker is inside its sign-up flow (no public page or endpoint; `/address` is a 404 and `agents.md` points to `/pricing`, which resolves by delivery area). Entering addresses into a third-party company's live sign-up form unattended was not done without the user's explicit OK. **Open item for the user:** approve a 10-address run through the real checker (in the user's browser).

## What was done instead
Independent check of the gate's utility assignment against the **City of Austin's official "Austin Energy Service Area" polygon** (data.austintexas.gov resource `w5fd-ctq4`, raw file in `data/raw/austin_energy_service_area/`, SHA-256 in SHA256SUMS) — a different source from the HIFLD mirror the gate used.

(No passing Travis home lies outside every co-op polygon — the HIFLD co-op polygons overlap essentially all of Austin, so the overlap tie-break decided every pass.)

## Fix
Where a utility publishes its own official service-area polygon, it replaces the HIFLD approximation in `core.territories` (new manifested source `austin_energy_service_area`, pipeline `territory_overrides`). Result after the fix: see "After" below.
