# T0-H4 — Houston / Dallas / Harris County permit feed verification

Done by: Claude subagent (T0-H4), 2026-09-26 04:05 UTC

Vendor claim under test: "Houston stopped publishing permit activity reports on
2025-12-01" and "Dallas's open feed stops at Dec 2019." Both checked directly
against the live sources below. **Verdict: both claims are wrong on the specific
date, though both point at a real problem.**

## City of Houston

### Verdict: LIVE (weekly cadence, ~1 week lag) — vendor claim is FALSE as stated

The vendor is half-right: the Houston **Planning & Development Department**
page did stop linking reports around Dec 1 2025, but the reports themselves
did not stop — they moved to a different City of Houston domain and continue
weekly through the present.

**Primary evidence (fetched directly):**

- `https://www.houstonpermittingcenter.org/news-events/permit-activity-reports-now-available`
  (curl, 200 OK) states verbatim: *"Permit Activity Reports are now available
  on the Houston Permitting Center website... Reports dated prior to December
  1, 2025 are still available on the Planning and Development Department
  website."* This is the announcement of a **relocation**, not a shutdown.
- `https://www.houstonpermittingcenter.org/sold-permits-search` (curl, 200 OK)
  lists a "Permit Activity Report Archives" section with individual weekly
  `.xlsx` links running continuously from **December 1, 2025** through
  **September 7, 2026** (the newest listed at fetch time), e.g.:
  `.../sites/g/files/nwywnm431/files/2026-09/Sept%207-13.xlsx`
- Downloaded that latest file directly:
  `curl -sL -o houston_permit_activity_sept7-13_2026.xlsx "https://www.houstonpermittingcenter.org/sites/g/files/nwywnm431/files/2026-09/Sept%207-13.xlsx"`
  → HTTP 200, 32,174 bytes, SHA-256
  `1c001ae0815a0566c8001e09539fcd8d0478a70802ba20267939a2e5affb37bf`
  (saved under this session's scratchpad `T0-H4/`).
  - Report header: `From: 2026/09/07` to `To: 2026/09/14`.
  - 317 data rows. Actual max `Permit Date` in the file: **2026-09-13**
    (min 2026-09-08). Fetched 2026-09-26, so the feed runs about 2 weeks
    behind "now" — consistent with a weekly publish-and-lag cadence, not a
    dead feed.
- Legacy page `https://houstontx.gov/planning/DevelopRegs/dev_reports.html`
  (curl -L) 302-redirects to `/` then returns **HTTP 400** — this page is
  effectively dead/blocked for direct fetch, consistent with the department
  having stopped maintaining it.

**Fields (from the xlsx):** `Zip Code, Permit Date, Permit Type, Project No,
Address, Comments`. `Permit Type` values seen in the latest file: `Building
Pmt`, `Demolition`, `OCC-BLDG PMT` only — there is no dedicated
solar/battery/generator permit-type category, no lat/long, no valuation, no
contractor name.

**Residential battery/generator/solar identifiable? Partially — via free-text
`Comments` only.** Keyword-scanning the 317-row Sept 7–13, 2026 file for
SOLAR / BATTERY / GENERATOR / "PV " / "ESS" found 9 hits, including:
- `SF RESIDENTIAL SOLAR PANEL ADDITION 1-1-5-R3-B 2021 IRC`
- `NEW RESIDENTIAL SOLAR PANELS 2021 IRC`
- `ONE-STOP ESS, SINGLE FAMILY RESIDENTIAL` (ESS = battery energy storage)
- `2 NEW EXTERIOR 450 KW NATURAL GAS GENERATORS 1-1-2-M-B 2021 IBC` (commercial,
  not residential — illustrates the field is not reliably scoped to
  residential without also filtering on the R3/single-family text)
This requires text parsing of an unstructured comment field, not a
structured field/column — so "partially identifiable," not cleanly
identifiable, and electrical-only solar/battery permits may not appear in
this particular weekly report at all (it is a Building/Demolition/OCC permit
report; a pure electrical PV-tie-in permit could be filed under a different
report the fetch did not surface).

**Also found, noted as separate/stale — not the live feed:**
- CKAN dataset `residential-building-permits` on `data.houstontx.gov`
  (`https://data.houstontx.gov/dataset/525772a1-0b4b-4d55-9b43-4d3b589fe1b7/resource/c9cef716-4d81-4dac-9b05-d19acddf159f/download/summary_residential_permits.xlsx`,
  curl -sL 200 OK, SHA-256
  `7ee9aae44d172eaab388f5bdaa91b1899fef3d72d0784c8ecd328ec0c1b5025d`, saved to
  scratchpad). This is a **monthly aggregate count** (Year, Month, Single
  Family, Multi-Family, Residential — no addresses, no permit-level rows).
  Last row: `2025, 12, 293, 1510, 1803`. File `last_modified` per the CKAN API
  (`package_show?id=residential-building-permits`) is `2026-05-01`, with no
  rows for 2026 months — this dataset itself is stale relative to today and
  is not permit-level data regardless.
- Houston Public Works / COHGIS ArcGIS Hub open data
  (`https://opendata-cohpwe.hub.arcgis.com/`, DCAT feed queried directly)
  has "Mobility Permits" / "SCPS Permits" layers, all last modified
  **2021-10/11** — these are right-of-way/traffic-control permits, not
  building permits, and are stale.

## City of Dallas

### Verdict: STALE / DEAD for the machine-readable feed — vendor claim is directionally right, factually wrong on the exact cutoff date

**Primary Socrata dataset checked:**
`https://www.dallasopendata.com/resource/e7gq-4sah.json`
(dataset id `e7gq-4sah`, "Building Permits", found via
`https://api.us.socrata.com/api/catalog/v1?domains=www.dallasopendata.com&q=permit`).

- `issued_date` is a **text** field (`dataTypeName: text`, confirmed via
  `https://www.dallasopendata.com/api/views/e7gq-4sah.json`), so naive
  `$order=issued_date DESC` / `max(issued_date)` sort as strings and are
  misleading (they returned `12/31/19`, which is an artifact of `MM/DD/YY`
  string comparison, not the true latest row).
- Corrected by querying row counts per year and month with
  `$where=issued_date like '<pattern>'`:
  - `.../e7gq-4sah.json?$select=count(*)&$where=issued_date like '%/20'` →
    27,459 rows exist in 2020 (proves data continues past 2019, contra the
    vendor's literal "stops at Dec 2019").
  - Per-month breakdown for 2020 (`like '<mm>/%/20'`) shows data through
    **August 2020** (3,415 rows) and zero rows for Sep–Dec 2020.
  - Per-day breakdown for August 2020 (`like '08/<dd>/20'`) shows the last
    day with rows is **2020-08-29** (3 rows); nothing on 08-30 or 08-31.
- **True latest record date in this dataset: 2020-08-29**, not Dec 2019 as
  claimed, but still over 5 years stale as of today (2026-09-26).
- Dataset metadata (`rowsUpdatedAt` in the views API) = epoch `1598778914`
  = 2020-08-30T09:15:14Z, consistent with the row-level finding: the dataset
  was last refreshed the day after the last permit it contains.

**Other Dallas building-permit sources checked (none live):**
- `ync5-xnfn` "Commercial Permits Activity Dashboard" on dallasopendata.com —
  confirmed **not queryable via SoQL** (`.../resource/ync9-xnfn... .json`
  returns `{"error":true,"message":"no row or column access to non-tabular
  tables"}`); it is a Tableau-style dashboard, not a machine-readable dataset.
- ArcGIS Hub `egisdata-dallasgis.hub.arcgis.com` (DallasGIS org), found via
  DCAT feed (`.../api/feed/dcat-us/1.1.json`) and ArcGIS item search
  (`https://www.arcgis.com/sharing/rest/search?q=Building%20Permits%20Fiscal%20Year%202023`):
  - **"Building Permits for Fiscal Year 2023 to 2024"** — Feature Service
    `https://services2.arcgis.com/rwnOSbfKSwyTBcwN/arcgis/rest/services/T_BU_Permits_FY2023_24/FeatureServer/0`.
    Queried directly via the ArcGIS REST API (`/query?where=ISSUE_DATE LIKE
    '%-<mm>-<yyyy>'&returnCountOnly=true`): rows exist for every month
    Oct 2023–Sep 2024 (14,336 total rows) and **zero** for any month outside
    that fiscal year. Fields include `PERMIT_TYPE, ACTIVITY, LAND_USE,
    SINGLE_FAMILY, MULTI_FAMILY, COMMERCIAL, ADDRESS, ZIP_CODE, ISSUE_DATE,
    CONTRACTOR_NAME, VALUE, COMMENTS, XCOORD/YCOORD` — richer schema than
    Houston's, and `LAND_USE`/`SINGLE_FAMILY` fields could support a
    residential filter, but there is no dedicated solar/battery/generator
    field — would still need `COMMENTS`/`ACTIVITY` text matching.
  - **"New Permits 1971-2024"** — Feature Service
    `https://services2.arcgis.com/rwnOSbfKSwyTBcwN/arcgis/rest/services/NewPermit_2008_2024/FeatureServer`.
    Its own ArcGIS item description states verbatim: *"This data was pulled
    from the Posse system on November, 2024 by Planning & Development
    Department GIS/Technology Staff... This is data for the fiscal year
    with no updates planned."* — i.e. Dallas itself documents this as a
    one-time historical extract, not a live feed.
  - No FY24-25 or FY25-26 building-permit layer exists under this ArcGIS org
    at the time of check (item search for the org's building-permit items
    returned only the FY23-24 layer, the 1971-2024 snapshot, and two
    dashboards built on top of them).

**Conclusion for Dallas:** every building-permit source found — the Socrata
dataset (stops 2020-08-29), the FY23-24 ArcGIS layer (stops Sep 2024, one
fiscal year, explicitly "no updates planned"), and the 1971-2024 snapshot
(explicitly static) — is a **dead, one-time or once-refreshed extract**, not
a live feed. The vendor's specific date (Dec 2019) is wrong, but the
underlying claim ("Dallas's open feed is not current") is correct: nothing
live or automatically updating was found for City of Dallas building
permits as of 2026-09-26.

## Harris County (unincorporated areas)

### Verdict: NO bulk/open-data or API source found — lookup-only tool exists

- `https://epermits.harriscountytx.gov/PublicProjectStatus.aspx` returns
  HTTP 200 but is a **single-record lookup form** (search by project/permit
  number or address), not a bulk export or API. No pagination or bulk query
  parameters were found.
- `https://oce.harriscountytx.gov/Services/Permits/Documents` returns HTTP
  200; it is a document repository (forms, guides), not permit-level data.
- Searched ArcGIS for a Harris County–owned permit layer:
  `https://www.arcgis.com/sharing/rest/search?q=Harris%20County%20building%20permits&f=json`
  — no Harris County–owned (county engineer / county government) permit
  feature layer among the results (results were unrelated orgs: Kinder
  Institute parcel-permit research layers, other cities' items).
- `WebSearch` for "Harris County Engineering permits ArcGIS REST" /
  `site:harriscountytx.gov permit report xlsx` surfaced only the same
  lookup tool (`eng.hctx.net/permits/Permit-Information-Tool`, an
  address/map search UI) and a note that bulk permit/plan records require
  an Open Records Request to the County Engineer's office.
- **No live, machine-readable, bulk building-permit source for
  unincorporated Harris County was found.** This does not block T0-H4's
  acceptance (Houston/Dallas only), but is recorded per the ticket's ask to
  "note Harris County (unincorporated) permit sources if any."
