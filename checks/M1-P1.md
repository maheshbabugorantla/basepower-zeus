## Notes / deviations

- `pipelines/config/counties.yaml` is parsed by a tiny hand-rolled loader in
  `parcels.py` rather than PyYAML: PyYAML is not a declared dependency in
  `pipelines/requirements.txt`, and the ticket's own acceptance command
  (`uv run --with-requirements requirements.txt`) installs only that file's
  pinned packages. The loader supports exactly counties.yaml's flat two-level
  shape (documented in `parcels.py`); if a future county needs more than that,
  add PyYAML to `requirements.txt` instead of growing the parser.
- The resumable cursor tracks `byte_offset` (the zip member's stream position,
  always a fixed-width record boundary) plus `rows_in`/`loaded`/`filter_drops`.
  On resume, the module re-scans PROP.TXT from byte 0 up to `byte_offset` to
  rebuild the in-memory de-dup `seen` set (the export's PROP.TXT member is only
  ~129 MB compressed, so this full pass costs low single-digit seconds) before
  continuing to load from `byte_offset` onward — no resume was actually needed
  for this backfill (single uninterrupted run), so this path is implemented per
  contract but untested against a real interrupted run.
