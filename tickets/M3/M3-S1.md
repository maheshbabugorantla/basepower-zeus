# M3-S1 — Migration 0301: ERCOT prices, grid value, load zones, outage metrics

## What to build

ERCOT price and grid-value tables, county-to-load-zone table, longest-event and Beryl-peak outage metrics, renormalized score, `api.signals_used`.
core.grid_value_lz also carries scarcity_days (see M3-P1) and each home carries base_capture ('full' | 'partner' | 'backup_only' |
'not_served'), derived from the already-loaded core.retail_market: Base earns ERCOT/VPP value only where it is the retail provider
(deregulated TDUs = full; co-ops = partner; municipal utilities such as Austin Energy = backup_only, per Base's own service tiers).
Grid-value and scarcity terms count only where base_capture is full or partner; for backup_only homes they are NULL with reason
'base_sells_backup_only_here' (never zero, never a spread number). Anchored absolute terms (value / 90th-percentile anchor across
the 8 load zones, capped at 1) — never percentiles.

## Acceptance criteria

- [ ] Migration applies cleanly
- [ ] `api.signals_used` lists which signals each home was scored on
- [ ] Every Austin Energy home has base_capture = backup_only and a NULL grid-value term with reason
