# M1-S1 — Migration 0101: TCAD parcels + geometry, block groups, permits, score v0, ranked views

## What to build

Parcels come from two official Travis County sources (see `checks/T0-H3.md`), loaded by two parallel tickets:
`core.parcels` (attributes from the TCAD 2026 Certified Appraisal Export `PROP.TXT`, filled by M1-P1) and `core.parcel_geoms`
(polygon + centroid from the Travis County `TCAD_public` layer, filled by M1-P4). Both key on TCAD `prop_id`; `geo_id` (10-digit,
e.g. `0174230307`) is the permit join key. `core.parcels` columns at minimum: prop_id, geo_id, county_fips, prop_type_cd,
imprv_state_cd, land_state_cd, hs_exempt, ov65_exempt, situs fields, market_value, tax_year, source_id. Do not store owner names.
Gate columns derived in views: single-family = `imprv_state_cd` or `land_state_cd` starts with `A1` (Texas PTAD category A1);
owner-occupied = `hs_exempt = 'T'` (homestead flag, replaces the situs = mailing proxy). Also `core.block_groups`, `core.permits`,
`core.permit_labels`, `ops.label_queue`; score v0 (backup intent only); `api.blockgroup_scores`, `api.top_homes`, `api.home_detail`,
`api.join_rate` (permit-to-parcel join rate on geo_id), `api.classifier_precision`; plus parcel gate counts (not single-family,
not homestead) so M2's gate funnel can extend them.
M0 seeded `ops.refresh_policy` with a `parcels` key; replace it with the real source keys `tcad_export` and `tcad_geometry` (both backfill-only).
