# M1-P1 — Travis parcel attributes from the TCAD 2026 certified appraisal export

## What to build

Load `core.parcels` from the TCAD **2026 Certified Appraisal Export (July 2026)**:
`https://traviscad.org/wp-content/largefiles/2026%20Certified%20Appraisal%20Export%20Supp%200_07182026.zip` (557 MB zip, ~18 GB unzipped; already downloaded to `data/raw/tcad/`, SHA-256
`62d0d1cd22b03f31db8d3986160eb181c5d00044df98a303fce9e17a44e9aa02`). Upload the zip unchanged to Storage (resumable upload; the
bucket allows 2 GiB) and write its manifest. Also manifest the layout zip (Legacy 8.0.33 layout, SHA-256
`c51352d2eba2f436c82b88ad156ebcc9a1d9c7fd546aee06bcfc83e69d61535b`) and take field positions from its XLSX, not from memory.
Stream `PROP.TXT` (4.9 GB fixed-width) straight out of the zip without extracting to disk. Key 1-based positions from the layout:
prop_id 1–12, prop_type_cd 13–17, geo_id 547–596, situs_street 1050–1099, situs_city 1110–1139, situs_zip 1140–1149,
hs_exempt 2609, ov65_exempt 2610, imprv_state_cd 2732–2741, land_state_cd 2742–2751, market_value 4214–4227, situs_num 4460–4474.
Keep only `prop_type_cd = R`. De-duplicate multi-owner rows (partial_owner / udi_group) to one row per prop_id. Never load owner names.
Record drop counts per filter in `ops.pipeline_runs`. The load is too big for a 300 s Vercel call: run it through the CLI
entrypoint (`runner = cli`) with a resumable byte-offset cursor. `counties.yaml` declares each county's parcel adapter
(Travis: `tcad_certified_export`), so Harris (M3) plugs in a different adapter by config.
