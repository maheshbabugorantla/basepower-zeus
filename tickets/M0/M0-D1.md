# M0-D1 — Scaffold web (Next.js) and pipelines (FastAPI) as two deployable Vercel projects

## What to build

`web/`: Next.js App Router, server-only DB access (`web/lib/db.ts` on `POSTGRES_URL` or Supabase with `SUPABASE_SECRET_KEY`;
never a `NEXT_PUBLIC_` key for data). `pipelines/`: FastAPI that auto-registers `/cron/<name>` for every module in
`pipelines/sources/` and rejects any request without `Authorization: Bearer $CRON_SECRET` (401). Shared helpers in
`pipelines/pipelines/core/`: fetch → upload raw to Storage bucket `raw` keyed by source/date/sha256 → `ops.source_manifest` row →
load → `ops.pipeline_runs` row with cursor and filter drop counts. `python -m pipelines.run <source> --backfill` runs the same
entrypoint from the CLI with `runner = cli`.

Platform facts (differ from the spec): Vercel **Hobby** plan, so functions max out at **300 s** and 2 GB, crons run at most once a day
(±59 min), one concurrent build. Size backfill chunks to finish well under 300 s. `POSTGRES_URL` is the **transaction pooler** —
disable prepared statements (psycopg `prepare_threshold=None`). Migrations and CLI backfills use `POSTGRES_URL_NON_POOLING`
(session pooler). The secret key env var is `SUPABASE_SECRET_KEY` (not `SUPABASE_SERVICE_ROLE_KEY`). PostGIS lives in
schema `extensions`. `.vercelignore` excludes `data/raw/`. `.env.example` holds names only.

## Acceptance criteria

- [x] `vercel deploy --cwd web` and `vercel deploy --cwd pipelines` (linked to `base-power-zeus` / `base-power-zeus-pipelines`) both produce previews
- [x] `curl` to a pipelines cron route without the bearer token returns 401
- [x] CI runs `scripts/no_mock_check.py`, `pytest pipelines`, and the web tests on every PR
