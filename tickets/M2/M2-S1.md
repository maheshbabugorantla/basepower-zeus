# M2-S1 — Migration 0201: territories, gate, need signals, score v1 with weights

## What to build

Territories, Base service areas, utility crosswalk, ACS, emPOWER, ZCTA, flood tables; gate columns; score v1 = weighted mean
of percentile ranks over available signals with top-3 reason codes; `api.top_homes(weights)`; `api.gate_counts`.
Outage exposure is per DISTRIBUTOR (user decision): `core.utility_reliability` (EIA utility number, name, data year, SAIDI/SAIFI/CAIDI
with and without major event days, early_release flag, source_id) and `core.county_customers` (EAGLE-I MCC.csv customer counts).
A home's outage signal = SAIDI (with major event days, latest year available) of the distributor whose territory contains it,
via the crosswalk; null with reason where the distributor has no EIA figure (e.g. Oncor, Bluebonnet 2025). Performance split (M1 lesson — live spatial joins timed out in production): PRECOMPUTE only input-independent work
into indexed materialized tables refreshed by the refresh_scores pipeline step after loads — per-home gate flags with reasons
and per-home signal values + percentile ranks (home→block group/territory/flood/ZIP joins, permits, ACS, emPOWER, distributor
SAIDI). Compute input-DEPENDENT work at request time: `api.top_homes(weights jsonb, county_fips text)` as a SQL function that
takes the slider weights, computes score = Σ wᵢ·pᵢ / Σ wᵢ over each home's available signals plus top-3 reasons (largest wᵢ·pᵢ),
orders and limits 50; must return in < 1 s. Never materialize a weighted score. `api.county_outage`
gains `hours_per_customer` = customer_hours_out / customers. Never present a county total as a home's value.
