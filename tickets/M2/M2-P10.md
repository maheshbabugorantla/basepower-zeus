# M2-P10 — Household income and prime-age signals (ACS block group)

## What to build

User request: median household income and working-age demographics as indicators of qualified customers (six-figure households
in their prime spending years). Use the ACS 2024 5-year at BLOCK GROUP level (finer than ZIP; the unit we already score on) from the
same Census API source as the existing ACS load: median household income B19013_001E; share of households earning $100k+ =
sum(B19001_014E..B19001_017E) / B19001_001E; share of population aged 35-64 from B01001 (male 013E-019E + female 037E-043E) /
B01001_001E. New raw file with its own manifest row; suppressed/annotated Census values (e.g. -666666666) stay null with a reason,
never zero. Scoring (done together with M2-P9's scoring pass so the per-home table is rebuilt once): anchored terms like the other
signals (income_100k_share and age_35_64_share as shares scaled to the Travis 90th percentile, capped at 1); labelled on screen as
neighborhood figures. Re-run `python -m pipelines.check ranking`: report each new signal's single-signal AUC and the gain over the
current default-weight score (home value overlaps income), and set default weights from that evidence in core.default_weights.

## Acceptance criteria

- [ ] ACS values for 3 block groups match data.census.gov / the Census API directly
- [ ] Evaluation report shows AUC with and without the new terms; default weights updated from it
- [ ] Home page and breakdown show the income and age lines as neighborhood figures with provenance
