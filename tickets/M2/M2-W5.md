# M2-W5 — Explain why a home was chosen: score breakdown plus a Gemini summary for GTM

## What to build

User request: it is not clear how the score is derived; a contextual summary (Gemini) should tell GTM why a home is chosen.
Two layers, deterministic first. (1) Score breakdown: api.home_score_breakdown(prop_id, weights jsonb) returns, per signal, the raw value
with units, its percentile, the weight, and its contribution w_i*p_i/sum(w) (same terms as api.top_homes_weighted incl. 1-flood_pctile),
plus which signals were missing and why. Render it as a stacked contribution bar plus a table on the home page and as an expandable row
on /ranking, with one plain sentence on the formula ("score = weighted average of the percentiles below; missing signals are dropped,
not zero-filled"). (2) "Why this home" summary: a server route calls Gemini (GEMINI_API_KEY, server-only; pick a current Flash model from
the models list) with ONLY the breakdown facts plus distributor, market, block-group context, and asks for 2-3 sentences a GTM rep can
say on a call. Grounding guard: every number in the reply must appear in the input facts, no dollars, no invented facts; if the guard
fails or Gemini errors/timeouts (8 s), show the deterministic template sentence instead. Cache results in core.home_summary keyed by
(prop_id, weights hash, facts hash) with model id, prompt version, generated_at; label on screen "AI summary (Gemini) of the numbers
below" with the model id. Load the summary client-side after the page renders so the page never waits on Gemini.

## Acceptance criteria

- [ ] Home page shows the contribution bar; contributions sum to the displayed score (±0.001)
- [ ] Summary for 3 real homes cites only numbers present in the breakdown (guard test on real rows)
- [ ] Gemini failure path shows the template sentence
- [ ] Page first paint does not wait on Gemini; cached summary returns < 100 ms
