# M2-W5 — Explain why a home was chosen: score breakdown plus a pre-generated Gemini summary for GTM

## What to build

User request: it is not clear how the score is derived; a contextual summary (Gemini) should tell GTM why a home is chosen.
Security (user decision): the public site never calls Gemini, so nobody can burn credits through it. Summaries are pre-generated offline.
(1) Deterministic breakdown: api.home_score_breakdown(prop_id, weights) returns per signal the raw value, percentile, weight and contribution
w*p/sum(w) over available signals (same terms as the ranking, incl. 1 - flood_pctile); missing signals are dropped with a plain reason.
Rendered as a contribution bar + table that follows the sliders, with one sentence on the formula.
(2) Summary: pipeline home_summaries (CLI/cron, GEMINI_API_KEY + BRIEF_MODEL on the pipeline side only) writes 2-3 GTM-ready sentences per
home at equal weights into core.home_summary, after a grounding guard (every number must appear in the facts; else the deterministic
template is stored). The web app only does a primary-key read; with no stored summary it shows the deterministic template.

## Acceptance criteria

- [ ] Contributions sum to the ranking score (±0.001) on real homes
- [ ] No web code path calls Gemini; GEMINI_API_KEY is not set on the web project
- [ ] Guard rejects a reply with a number not in the facts; template shown instead
- [ ] Stored summary read < 100 ms
