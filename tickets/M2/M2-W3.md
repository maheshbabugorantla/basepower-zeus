# M2-W3 — Map in sync with the weighted ranking

## What to build

User feedback: the Top homes table and the map disagree — the map colours block groups by the M1 v0 backup-intent score while the
table ranks homes by the M2 weighted score, and sliders only change the table. Add api.blockgroup_scores_weighted(weights jsonb, county_fips text)
(percentile of the mean weighted home score of each block group's gate-passed homes, using exactly the same per-signal terms as
api.top_homes_weighted incl. the corrected flood direction; < 1 s); a no-store route the map calls on every debounced slider change to
re-colour via feature-state (geometry stays cached from api.blockgroup_geojson); and numbered pins for the current top 50 at their parcel
centroids (primary-key lookups only). Hovering a table row highlights its pin and block group; hovering a pin highlights its row.

## Acceptance criteria

- [ ] Map colours and the table use the same weights: the top-1 home's block group is in the darkest map class
- [ ] Moving a slider re-colours the map and moves the pins
- [ ] Row hover ↔ pin hover highlight each other
- [ ] Every request-time query < 1 s
