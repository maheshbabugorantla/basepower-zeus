# M4-P4 — XGBoost backtest model with spatial cross-validation and SHAP

## What to build

Supervised model on the real ice-storm outcome. Label: a gated home received a battery or generator permit between
2023-03-01 and 2024-02-29 (from the since-2010 permit history M4-P2 loads). Features: only values known before 2023-01-01
(prior backup/solar/panel permits, parcel facts, block-group ACS, emPOWER, flood, distributor SAIDI/SAIFI for the latest year
before 2023, grid value). XGBoost classifier with class weighting (positives are rare); evaluate with GROUPED spatial
cross-validation holding out whole block groups (no neighbour leakage); report AUC, PR-AUC and top-vs-bottom-decile lift on
held-out folds, whatever they are. Fit the final model on all data with a fixed seed; write per-home predicted probability and
top-3 SHAP reasons to `core.home_model_score`, mean |SHAP| to `core.feature_importance`, and normalized per-signal importance as
`core.learned_weights`. The target is backup-intent adoption, a PROXY for Base demand; the model card must say so. Train from the
CLI, not a Vercel function. Extend `scripts/no_mock_check.py` with an explicit same-line marker
`# no-mock-check: seeded-model <reason>` that allows seeded RNG only in `pipelines/models/`; everything else stays banned.

Experiment protocol (pre-registered; thresholds fixed before the first run — a disappointing result is a FINDING, never a reason to redo):
- Baselines on the same grouped folds: B0 prevalence; B1 block-group prior backup-permit rate; B2 hand-weighted score v1 (equal
  weights); B3 logistic regression on the same features. Replication: rerun with features < 2024-01-01 and label Mar 2024–Feb 2025.
- Tuning: fixed grid (max_depth 3–6, learning_rate 0.05/0.1, ≤300 trees with early stopping) tuned on INNER folds only; budget 10
  configurations; every run is an immutable `core.model_runs` row (seed, feature-set hash, input manifest IDs, fold scheme, metrics).
- Progress signals (report all, with bootstrap 95% CIs where applicable): PR-AUC vs B0 (healthy ≥ 2× prevalence); top-decile lift vs
  B1/B2 (healthy: CI excludes them); AUC vs B2/B3; fold AUC std ≤ 0.05; train–test AUC gap ≤ 0.10; Brier score and reliability curve
  vs B0; SHAP top drivers physically plausible with expected signs; replication-year lift in the same direction; shuffled-label
  negative control (seeded) AUC ≈ 0.5 and lift ≈ 1.
- REDO (run is invalid, results void) when: any feature dated ≥ 2023-01-01; AUC > 0.95 or one feature > 50% of mean |SHAP| (audit for
  leakage/label proxy, drop, rerun); any block group in both train and test of a fold; shuffled-label control AUC > 0.55; same seed
  does not reproduce identical metrics. DATA-LIMITED (say so, don't tune): < 200 positives overall or < 20 in any fold → widen the
  label window or merge folds and document it. UNSTABLE: fold AUC std > 0.05 → simplify (shallower trees, stronger regularisation,
  fewer features) within the tuning budget.
- Verdict: every run ends with exactly one of PASS / REDO-INVALID (with the triggered rule) / FINDING (valid but does not beat
  baselines) recorded in checks/M4-P4.md. Learned weights are exposed to the app only on PASS where the model beats B2 on held-out
  top-decile lift; otherwise api.learned_weights carries null with reason "model did not beat the team's weights".
