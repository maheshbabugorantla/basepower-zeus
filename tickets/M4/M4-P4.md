# M4-P4 — XGBoost backtest model with spatial cross-validation and SHAP

## What to build

Supervised model on the real ice-storm outcome. Label: a gated home received a battery or generator permit between
2023-03-01 and 2024-02-29 (from the since-2010 permit history M4-P2 loads). Features: only values known before 2023-01-01
(prior backup/solar/panel permits, parcel facts, block-group ACS, emPOWER, flood, distributor SAIDI/SAIFI for the latest year
before 2023, grid value). XGBoost classifier with class weighting (positives are rare); evaluate with GROUPED spatial
cross-validation holding out whole block groups (no neighbour leakage); report AUC, PR-AUC and top-vs-bottom-decile lift on
held-out folds, whatever they are. Fit the final model on all data with a fixed seed; write per-home predicted probability and
top-3 SHAP reasons to `core.home_model_score`, mean |SHAP| to `core.feature_importance`, and normalized per-signal importance as
`core.learned_weights`. The target is backup-intent adoption, a PROXY for Base demand; the model card must say so. Train from the
CLI, not a Vercel function. Extend `scripts/no_mock_check.py` with an explicit same-line marker
`# no-mock-check: seeded-model <reason>` that allows seeded RNG only in `pipelines/models/`; everything else stays banned.

## Acceptance criteria

- [ ] pytest pipelines/tests/test_backtest_xgb.py (asserts every feature date < 2023-01-01 and that no block group appears in both train and test of any fold)

- [ ] Re-running with the same seed reproduces identical metrics
